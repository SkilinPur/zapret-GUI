# Changelog

Все заметные изменения проекта. Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [1.0.25] — 2026-08-13

### Изменено
- Вкладка «Обновление» переработана в **три одинаковых модуля** — «Программа (GUI)», «Ядро nfqws», «Стратегии Flowseal»: каждый показывает текущую и доступную версию, статус («актуально» / «доступно обновление») и свою кнопку обновления. Сверху — «⟳ Проверить всё» и «⬇ Обновить всё» (обновляет устаревшие модули по очереди). Программа обновляется через git pull с предложением перезапуска, ядро и стратегии — отдельными командами.

## [1.0.24] — 2026-08-13

### Добавлено
- Вкладка «Обновление»: блок **«Компоненты»** — показывает установленную и доступную версии ядра **nfqws** (bol-van/zapret) и ревизию **стратегий Flowseal**, с кнопками «Скачать nfqws» / «Обновить стратегии» прямо из вкладки. Проверяется вместе с «Проверить обновления».
- При обновлении стратегий запоминается установленная ревизия (`.flowseal-rev`) для сравнения с последней на GitHub.

## [1.0.23] — 2026-08-13

### Изменено
- **Обновлены nfqws и стратегии одной проверенной связкой:** ядро nfqws v72.9 → **v72.13** (последний стабильный релиз bol-van/zapret), стратегии — на актуальный **Flowseal main** (добавлены новые `general_alt13.bat`, `general_exp.bat` и свежие рецепты). Проверено: все 25 стратегий парсятся и принимаются новым ядром.
- Обновление стратегий теперь копирует и **bin-шаблоны из репозитория Flowseal** (`ACTIVE_DISCORD_UDP.bin`, `ACTIVE_GAME_UDP.bin`, `stun2.bin` и др.), которых нет у bol-van — иначе новые стратегии Discord не запускались бы.
- `ensure_bin_files` тянет недостающие шаблоны из двух источников (сначала `bin/` Flowseal, затем `files/fake` bol-van); для старых имён, которых нет нигде (`quic_initial_dbankcloud_ru.bin`), подставляется шаблон того же типа.

## [1.0.22] — 2026-08-13

### Исправлено
- **Демон снова можно запустить после остановки.** Прошлый фикс (killpg) не помогал полностью: демонизированный nfqws уходит в отдельную сессию (`setsid`), и pipe stdout оставался открытым даже после завершения группы → поток `DaemonWorker` всё равно висел, а «Старт» игнорировался. Теперь чтение вывода неблокирующее (select с таймаутом 0.2 с + флаг остановки) — поток гарантированно завершается при `stop`/`terminate`, независимо от осиротевших потомков.
- **Чистый выход из приложения:** таймеры автопроверки обновлений и индикатора останавливаются при закрытии окна, чтобы не срабатывали после завершения работы (иначе поток `CheckWorker` уничтожался «на бегу» и падал с «QThread: Destroyed while thread is still running»).

## [1.0.21] — 2026-08-13

### Исправлено
- **Демон больше не «залипает» после остановки.** `service.sh daemon` держит фоновый `sleep infinity`, который после SIGTERM оставался жить и держал pipe stdout открытым — поток `DaemonWorker` вечно ждал EOF и не завершался. Из-за этого после «Остановить» повторные нажатия «Старт» игнорировались («демон уже запущен»). Теперь процессы запускаются в отдельной process group и завершаются вместе с потомками (`stop`/`terminate` убивают всё дерево).
- Сообщение «! демон уже запущен» вместо молчаливого игнорирования, если демон ещё останавливается.

## [1.0.20] — 2026-08-12

### Исправлено
- **Остановка из трея больше не закрывает программу**: фоновый воркер `service.sh kill` раньше уничтожался сборщиком мусора, пока его поток ещё работал, и PySide6 ронял приложение («QThread: Destroyed while thread is still running»). Теперь воркер удерживается до завершения потока.
- **Выход из приложения во время фоновых операций не падает**: при закрытии окна все работающие потоки (демон, воркеры команд, проверка обновлений) безопасно завершаются через `stop`/`terminate` + `wait`, а не уничтожаются «на бегу».

## [1.0.19] — 2026-08-12

### Добавлено

- **Уведомление о падении nfqws**: если zapret неожиданно остановился, трей покажет предупреждение.
- Статус в подсказке иконки трея («работает» / «остановлен»).

- Цвета статуса: работает — зелёный, остановлен — серый (красный остался фирменным акцентом).
- Шрифты UI дополнены Inter/Roboto.

### Исправлено

- Дописывание `firewall_backend=auto` в root-owned `conf.env` больше не роняет скрипт (используется elevate).

## [1.0.17] — 2026-08-12

### Исправлено
- Вкладка «Права» всегда считала, что NOPASSWD не настроен: проверка вызывала несуществующую команду `service.sh status`. Теперь проверяется `service status`, и после настройки прав статус отображается корректно.
- Вкладка «Сервис» путала статусы «установлен и активен» и «установлен, но не активен»: остановленный сервис показывался активным, а кнопка «Запустить» была недоступна. Теперь статусы различаются верно.
- Просмотр логов на non-systemd системах показывал journalctl; теперь используется лог-файл `/var/log/zapret_discord_youtube.log`.
- Устаревшая переменная масштабирования `QT_AUTO_SCREEN_SCALE_FACTOR` заменена на `QT_ENABLE_HIGHDPI_SCALING`.
- После ошибки команды во вкладке «Статус» статус и кнопки теперь обновляются.
- Убран мёртвый код очистки пароля во вкладке «Права».

## [1.0.12] — 2026-08-11

### Исправлено
- Демон падал при запуске с «could not read bin/quic_initial_www_google_com.bin». Шаблоны поддельных пакетов `bin/*.bin` (quic_initial_*, tls_clienthello_*, stun) не было откуда взять: их нет ни в git-клоне стратегий, ни в архиве релиза zapret. Теперь при запуске (и при скачивании зависимостей) они автоматически скачиваются из `files/fake` репозитория bol-van/zapret и кешируются в `bin/`. Для имён, которых нет в zapret (`quic_initial_dbankcloud_ru.bin`, `tls_clienthello_max_ru.bin`, `tls_clienthello_4pda_to.bin`), подставляются шаблоны того же типа.

## [1.0.8] — 2026-08-11

### Исправлено
- Вкладка «Права»: кнопка «Настроить работу без пароля» больше не молчит. Раньше она запускала `sudo -n` (без возможности ввода пароля и без терминала), поэтому просто падала с ошибкой. Теперь запуск идёт через `pkexec` — появляется системное окно ввода пароля (polkit).
- Правильное имя пользователя при настройке: раньше скрипт, запущенный через sudo/pkexec, записывал правила для `root` вместо реального пользователя. Теперь имя определяется автоматически (`SUDO_USER`/`PKEXEC_UID` или явный аргумент).
- В sudoers добавлено правило `bash <каталог>/service.sh *` — без него все остальные команды GUI (запуск/остановка, конфиг, стратегии) работали бы только от root.
- Кнопка «Права» теперь активна всегда: если NOPASSWD уже работает, её нажатие обновляет правила (например, после обновления программы).
- Обновление больше не срывается, если `zapret-latest` был создан от root: GUI и CLI автоматически возвращают владельца каталога перед записью. Если авто-исправление недоступно, выводится готовая команда для ручного восстановления прав.
- В настройку работы без пароля добавлено право `chown` для каталога проекта, чтобы восстановление прав работало из GUI без ввода пароля.
